# 服务器运维插件

仅 NoneBot 配置 `superusers` 中的超级用户可在私聊使用。`system.bot_admins`、权限配置里的机器人管理员、群管理员、权限白名单和空权限配置均不能授予 shell 能力。插件权限开关关闭时，对超级用户也拒绝执行。

## 使用

1. 在私聊发送 `#服务器模式`，直接进入服务器模式。首次绑定「运维」人格；后续新消息使用独立命名空间 `平台:Bot#server:private:用户`。
2. 向 AI 描述运维任务。AI 使用 `tool_search` 找到延迟工具 `server_exec`。
3. 工具提交 `command`、可选绝对 `cwd`，立即返回 `job_id`。使用同一个工具传 `job_id` 查询输出；`cancel=true` 取消当前会话任务。
4. 只读查询按控制台「服务器运维 → 只读自动执行」的前缀表直接执行（`ls`、`ps`、`grep`、`docker ps/logs/inspect`、`systemctl status`、`journalctl` 等）；含分号、重定向、`$()`、反引号时一律确认，管道只有每一段都命中前缀才自动执行。其余命令——复杂 shell、解释器、下载、修改、删除、关机、停服务——保守进入人工确认。Bot 会把完整命令、目录和影响直接发给超级用户，超级用户像平时聊天一样回话即可（“行”“跑吧”“先别”“算了”都行）。AI 判断超级用户是明确同意后才调用确认工具执行；提问、犹豫、沉默、转而说别的事都不算同意，含糊时它会先解释再问。超级用户拒绝就放弃。

控制台「服务器运维 → 全部命令免确认」默认关闭；打开后除黑名单以外的命令都直接执行，不再逐条确认，适合测试或临时排障。配置修改后热加载，无需重启。
5. `#聊天模式` 直接回到普通私聊，并撤销待确认、取消在途命令。不再提供旧的开启、退出或状态查询命令，也不再需要回复固定口令。

模式开启期间，原有 `#人格`、`#清空对话` 作用于服务器会话。退出不清空历史；`#清空对话` 会销毁服务器会话（含短期历史与 A_Memorix 长期记忆，学习记录保留），并取消在途命令。再次开启不会覆盖用户后来选择的人格。聊天功能仍须正常启用、允许私聊并配置模型，本插件不私自修改核心聊天配置。

## 隔离与权限

- 模式只修改 Bot 命名空间，真实平台、会话类型、用户号不变。服务器会话默认禁止 Focus 接管；表达和黑话默认按控制台「学习 → 群表达 / 黑话 → 共享组」共享。学习共享、消息防抖、正在输入和分段回复都在控制台「服务器运维 → 会话能力」里单独开关。服务器会话与普通私聊的目标相同，不需要单独添加。
- A_Memorix 保留自己的 session 隔离与公共知识语义，不关闭记忆，不更改内核。
- 每次工具执行都复核真实 Bot/Event、私聊类型、superusers 超级用户身份、派生会话、模式和插件开关；执行中每 0.5 秒复核，撤销超级用户资格即终止任务。
- 确认工具只在存在已展示的待确认命令时对模型可见；提交命令的同一轮不能在当轮自我确认，必须由超级用户随后一轮真实消息触发。确认依据超级用户那轮的原话由模型判断，不是关键词匹配；提示注入理论上可能影响判断，超级用户只应在自己可控的环境里使用。
- 插件关闭或撤权后，仍把已开启的消息路由到服务器域，再拒绝生成/发送；不会把运维消息静默混进普通聊天。重新授权/开启插件后可退出模式。
- 服务器域仅允许 shell、确认、工具检索、完整结果读取和会话记忆查询，不继承其他业务插件的操作工具。

## 执行边界

- 命令以 **Bot 进程的实际系统权限** 运行，不提权。容器里的 Bot 操作容器，不保证能管理宿主机。
- Linux/POSIX 使用新 session/进程组，结束、取消、超时会杀整个进程组；故意通过其他服务、守护化或独立 session 逃逸的命令不受此清理保证。这不是沙箱。
- Windows 使用 Job Object，并通过 stdin 握手确保命令开始前已加入 Job；超时/取消/进程退出清理所属进程树。执行器无法创建/加入 Job 时拒绝执行命令。
- 单条命令上限 60 秒；每会话最多一个待确认或运行任务，全局最多四个。输出持续排空、最多保留 4000 字；不把无限输出先全部读进内存。
- 待确认命令 120 秒内有效；超时后需重新提交。
- 「全部命令免确认」会跳过整个确认环节，只剩黑名单拦截；风险最高，测试或排障结束后应关闭。
- 只读自动执行是前缀匹配，不是安全判定：`cat /etc/shadow`、`docker inspect`、`grep -r /` 也会直接跑，可能把敏感内容送进模型或长期占住会话；`date -s`、`hostname 新名`、`journalctl --vacuum` 这类会写数据的参数仍会确认。
- 提交前先过一次命令黑名单：控制台「服务器运维 → 命令黑名单」按正则匹配（不区分大小写），默认拦截删根、格式化/覆写磁盘、fork 炸弹等不可恢复操作，命中直接拒绝并记审计，不进入确认。黑名单只防误操作和被诱导的常见写法，改规则或换写法都能绕过，不是安全边界。
- 任务是一次性非交互 shell，不提供持续终端；`cd` 不影响后续任务，需要显式传 `cwd`。交互输入、长期服务和后台守护进程不属于任务式执行的可靠用法。
- 危险判断只作交互确认，不是可靠的命令安全分析。任意 shell 可以读取文件、访问网络和修改数据，超级用户授权此插件即授予 Bot 所拥有的执行能力。

## 数据

- 模式开关：`config_dir("server_admin")/mode.json`，通过 ConfigManager 原子保存；状态损坏时拒绝路由回退。
- 插件配置：`config_dir("server_admin")/config.json`，保存免确认开关、会话能力开关、命令黑名单和自动执行前缀；控制台修改后热加载。
- 运维人格按需播种到原人格目录：内容仍是已发布种子时随版本自动升级，用户改过的内容不覆盖。会话绑定只补缺，不覆盖手动选择的人格。
- 审计：`data_dir("server_admin")/audit.jsonl`，记录提交、黑名单拦截、展示确认、超级用户确认（含原话摘录）、执行开始/结束、取消和模式切换。5 MiB 轮转，保留三份旧日志；POSIX 新建权限 0600。命令执行前无法写审计则拒绝启动。
- 审计不保存 stdout/stderr，但完整命令本身也可能含密钥；输出可能进入私聊、AI 提供商、历史与长期记忆。避免在命令参数中写密码，敏感输出应让 AI 使用脱敏查询。此插件不保证自动识别所有秘密。
- 待确认与任务结果在内存，重启不恢复执行，不会重放命令；终态结果最多保留最近 100 条。

## 验证

`python -m unittest tests.chat.test_server_admin -q` 只运行无害命令与进程清理测试；不会运行删除、格式化、关机或停服务命令。平台相关进程树清理应在目标部署系统上再执行回归。
