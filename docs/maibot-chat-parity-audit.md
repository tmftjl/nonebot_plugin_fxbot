# FxBot 与本地 MaiBot 功能核查

## 消息目标与上下文补齐（2026-11-03）

再次对照 `D:/project/MaiBot` 的 `062d45c` 实际实现，补齐普通消息和 Focus 入站的原始时间、发言人、引用和 @ 机器人信息；真实机器人发言使用带 `is_self_message` 的聊天内容，不与 Planner 自身的 assistant 工具协议混淆。跨日插入日期提示。启动只回灌配置窗口的一半真实消息，并使用上游原版离线分档与上下文恢复提示。

多人批次以最新消息作为请求身份，各条消息保持原作者；运行中收到消息时更新触发锚点、人物参考与调用者运行时。被动模式在模型请求前固定最新目标，主动模式仍允许选择本会话历史目标，不添加“只能回最近 N 条”或“必须回触发消息”等额外限制。已引用回复过目标时注入上游的补充而非重复提醒。

Planner 调用、实际发言与工具返回按执行顺序进入历史，发给模型时保持调用和返回的协议原子段。裁切和滚动状态压缩按内部循环执行，不再等数分钟的整个长对话结束才处理；工具回合保护边界包含真实触发消息。发送回执保存实际发出的正文、时间、消息 ID 与实际引用，而不是仅保存生成原文。修复撤回只增加内存代次却不更新数据库代次、导致后续轮次拒绝落库的问题；不改表、不转换或补写历史数据。

真实模型回放使用下载库中的用户上下文，并将待测问题按定向提问补入 @ 信息；缺失的历史机器人正文无法还原。两组问题分别选中了 `1076195593` 与 `844393827`，完整走完 Planner、回复器与模拟发送。未向真实群聊发送；这两次回放不代表模型永远不会自由选择旧话题。

## 既有核查记录

用户确认的引用上下文补齐：适配器输出的引用作者昵称、账号和最多 500 字原文预览随入站消息保存在现有 payload 中；原消息已离开上下文窗口时仍可看到 `[引用 昵称(账号)] 原文`。普通群消息、触发消息、Focus、目标切换和重启恢复使用同一快照，避免已入历史后丢弃引用预览或重复展示。OneBot V11 优先读取事件自带引用，缺失时一次查询同时取原文与作者，检查结果的消息和群归属；同一事件短缓存复用查询结果。引用源 ID 与机器人当前回复目标分开，不改表、不回填旧历史、不新增配置。

用户追加的群友身份标注：OneBot V11 适配器直接读取群消息事件的发言人角色，不查询成员接口。角色和群昵称在同一消息前缀中呈现为 `user="昵称" role="管理员"`；普通成员、管理员、群主均支持，缺失或未知角色直接省略。普通对话、多人合批、Focus 和重启恢复保留每条消息收到时的角色，不为旧历史补查身份，也不把触发者身份套到其他回复目标上。不新增配置或更改工具授权。

用户追加的机器人群身份背景：平台查询、角色解析和缓存均位于适配器层，本次仅实现 OneBot V11；QQ 官方及其他未实现平台不注入角色。只接受平台明确返回的 `owner`、`admin`、`member`，未知值不当作普通成员。按平台、机器人账号和群隔离缓存，成功保留 5 分钟、失败保留 30 秒，过期后按需查询，不监听身份变更、入群或重连通知。普通 Planner、回复器及 Focus 的会话参考会标明机器人自己在对应群的角色；这只是背景信息，不修改工具权限检查，也不授予发言人权限。

用户追加的作息人物背景：仅在“休息时间不回复”开启时，向普通 Planner、回复器和 Focus Planner 注入“只在上班时间水群，休息时打游戏、看电视或出去玩”的生活习惯，并读取实际配置的上班时间。关闭开关后不再注入，不新增配置，也不修改人格文件或上游原版模板。提示仅描述习惯，不要求模型编造某次离线的具体游戏、剧集、地点或同行者。

用户新增的 AI 作息控制（并非 MaiBot 原生配置）：`chat.work_time` 默认 `08:30-17:30`，`chat.rest_time_no_reply` 默认关闭。启用后按北京时间和中国法定工作日限制普通群聊、私聊、主动接话及 Focus；手动总开关仍优先。工作日日历来自 `NateScarlet/holiday-cn`，同时读取相邻年度处理跨年调休，本地缓存位于 `data/ai_chat/work_calendar/`。后台每分钟检查是否需要更新，成功后 24 小时内不再下载，失败 15 分钟后重试；缺失当年有效日历时暂停回复。消息处理和发送复核只查本地缓存，不逐条联网，也不清空历史或修改普通命令权限。控制台 schema 直接显示这两个字段，无需新增前端页面。

诊断数据保留：规划样本和轮次追踪各自保留 72 小时、各类全局最多 10,000 条；后台在启动时及每分钟清理过期和超量记录，写入路径不做额外扫描。门控观察仍仅在内存保留每会话最近 200 条。本策略不清理聊天历史、表达/黑话学习或 A_Memorix 长期记忆，不增加设置项；817 项回归与前端类型检查、构建通过。

后续明确要求：删除全局私聊暂停、单个私聊暂停规则及备用 Provider 配置和运行逻辑。私聊只由启用开关与白名单控制；每项任务使用单一 Provider，不做故障转移。“忽略命令前缀”继续保留，匹配消息（包括开头空白和带图消息）不进入对话、群聊历史或私聊历史。本次全库 799 项测试、前端类型检查与构建通过。
