# 控制台直接对话

控制台左侧「AI 对话 → 直接对话」是独立 WebUI 私聊渠道，不需要 QQ、官方 QQ 或其他真实 Bot 在线。
需要后端正常运行、配置可用的规划/回复模型，以及 AI 总开关和作息规则允许回复。

网页消息使用 `webui:console:private:<UUID>` 会话，经过入站守卫后交给正常 `ChatService.process_and_send()`，
保留 Planner、人格、记忆参考、正文过滤、发送守卫与生命周期审计。它不强制纯人格直聊，也不加入 Focus 共享组。

支持文字输入、逐段回复、新建独立会话、选择人格和回复模型、停止及清空。Enter 发送，Shift+Enter 换行，
输入法确认不会误发送。切换人格需先新建或清空，避免把旧人格上下文带给新人格。
模型选择是会话的回复模型绑定，规划模型仍遵循现有模型路由。

会话入口列表保存在浏览器本地，最多显示最近 20 个入口；历史沿用现有会话存储与私聊上下文条数。
配置为 0 时，本页仍显示刚发送的内容，但刷新后没有可恢复的历史。清空只处理本会话的短期历史，
不会删除长期记忆、学习资产或其他渠道会话。内存清空成功但持久化清理未确认时页面会提示。

首版只提供文字渠道，不提供图片、语音、表情、文件或群管理操作。工具由运行时允许列表限制，
在发现、搜索及执行时继续受核心权限和 Hook 限制；网页登录不被解释为 QQ 管理员身份。
可用工具包括现有网页检索、该会话记忆查询、工具搜索和结果读取，实际可用性仍由配置与运行状态决定。

接口统一使用控制台 Bearer 鉴权，前缀 `/fxbot/local-chat`：

- `GET /options`：人格及回复模型列表。
- `GET /<UUID>`：可见历史、绑定和运行状态。
- `POST /<UUID>/messages`：文字和 UUID 消息 ID，返回 NDJSON 事件流。
- `POST /<UUID>/stop`：按消息 ID 取消指定轮次，迟到请求不能取消新轮次。
- `DELETE /<UUID>`：先取消在途任务，再清空本会话短期历史。

网页断开响应流或退出页面会取消该轮生成；已进入传输队列的正文按核心发送语义记为可见，
不保证浏览器最终已经绘制。刷新可从持久化成功的可见记录恢复。消息 ID 在当前进程内去重，不自动重试模型请求。
最多 16 个并发轮次，每轮生成和发送最长 300 秒，回复传输队列最多 32 条事件。
反向代理应允许流式响应并设置至少 300 秒的响应超时，接口已设置 `X-Accel-Buffering: no`。

验证方式：正常聊天回归外，运行 `python -m unittest tests.chat.test_console_chat`；
前端运行 `npm run type-check`、`npm run build` 和 `node --test tests/local-chat-view.test.mjs`。
可用 `python tests/ui_local_chat.py --channel msedge` 验证构建产物的发送、恢复历史和桌面/移动端布局；
该脚本使用假 API，不发起真实模型请求，不读写生产凭据。
